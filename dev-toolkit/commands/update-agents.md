# 更新 AGENTS.md 文件

分析当前项目结构，更新和维护所有相关的 AGENTS.md 文件，保持精简完善的风格。

## ⚠️ 重要：使用子代理执行

**禁止在主 Agent 循环中直接处理**，必须使用 Task 工具调用子代理来完成任务，防止上下文爆炸。

## 执行流程

### 第一步：项目结构探索（使用 Explore 代理）

使用 Task 工具调用 **Explore** 类型的子代理来完成：

```
subagent_type: "Explore"
thoroughness: "medium"
```

任务内容：
1. 扫描项目中所有包和子模块的目录结构
2. 发现所有现有的 AGENTS.md 文件及其位置
3. 检测每个 AGENTS.md 的行数，标记超过 500 行的文件
4. 识别缺失 AGENTS.md 的重要模块/包
5. 分析项目的整体架构（包结构、主要功能模块）

返回结果应包含：
- 所有 AGENTS.md 文件列表（路径、行数）
- 需要精简的文件列表（超过 500 行）
- 需要新建的位置列表
- 项目架构概述

### 第二步：按模块更新文档（使用 General-Purpose 代理）

根据第一步的结果，**分批处理**，每个模块/包使用独立的 **General-Purpose** 子代理：

```
subagent_type: "general-purpose"
```

**批次划分原则**：
- 根目录 AGENTS.md：单独一个批次（最重要）
- 每 2-3 个相关的子模块：一个批次
- 大型模块：单独一个批次

**每个批次的任务**：
1. 如果文件超过 500 行，先执行精简操作
2. 分析该模块的代码结构和核心功能
3. 生成或更新 AGENTS.md 内容
4. 确保符合精简策略和更新原则

**重要**：使用并行的 Task 调用来同时处理多个独立批次，提高效率。

## 更新原则

1. **精简性**: 对于现有的AGENTS.md，只保留必要信息，避免冗余
2. **完整性**: 覆盖所有重要功能和API
3. **一致性**: 统一的文档格式和风格
4. **准确性**: 确保文档与代码同步
5. **效率性**: 当对单个 AGENTS.md 修改时，如预计使用编辑工具的次数超过 6 次，则不进行逐条编辑，直接覆写整个文件

## 自动精简策略

**重要**: 主动检测并精简过长的非主要 AGENTS.md 文件，防止文档爆炸：

1. **行数限制**:
   - 根目录主 AGENTS.md: 无行数限制（项目总体说明需要完整）
   - 子目录/包级别 AGENTS.md: 严格限制在 **500 行以内**

2. **检测与精简流程**:
   - 在更新任何 AGENTS.md 前，先检查其当前行数
   - 如果非主要 AGENTS.md 超过 500 行，**立即执行精简**
   - 精简后再进行正常的更新流程

3. **精简策略**（按优先级应用）:
   - 删除冗余的示例代码，只保留最关键的1-2个示例
   - 合并重复的说明，提取共性描述
   - 简化详细的实现细节，只保留接口说明和核心逻辑
   - 删除过时的历史变更记录
   - 将过于详细的参数说明改为表格或简要列表
   - 移除不必要的重复性章节标题和说明

4. **保留内容**（精简时必须保留）:
   - 包/模块的核心职责和功能概述
   - 主要的公共 API 和接口定义
   - 关键的依赖关系和架构说明
   - 重要的使用注意事项和限制

5. **执行要求**:
   - 每次更新时自动检查所有非主要 AGENTS.md 的行数
   - 发现超过 500 行时，主动告知用户并立即精简
   - 精简后输出精简报告（原行数 → 新行数，删减内容类型）

6. **重要信息保留策略**:
   - 如果精简过程中确认会丢失重要信息，可以在对应的文件夹中新建额外的 AGENTS.md 文件
   - 例如：原有 `lib/AGENTS.md` 过长时，可以创建 `lib/utils/AGENTS.md`、`lib/core/AGENTS.md` 等子模块文档
   - 优先考虑按功能模块拆分，而不是强行删减重要内容

## 文档引用策略

为了保持文档的关联性和避免重复，支持跨文档引用：

1. **引用格式**: 使用 `@PATH:行数-行数` 格式引用其他 AGENTS.md 的内容
   - 示例: `@lib/utils/AGENTS.md:15-30` 表示引用该文件的第15到30行
   - 示例: `@AGENTS.md:100-120` 表示引用根目录 AGENTS.md 的第100到120行

2. **引用场景**:
   - 避免重复描述：当多个模块共享相同的概念或接口时
   - 继承说明：子模块引用父模块的通用规则
   - 关联文档：相关功能模块之间的交叉引用

3. **引用原则**:
   - 使用引用来建立文档之间的联系，形成文档网络
   - 引用的内容应该是相对稳定的核心信息
   - 避免过度引用导致文档难以独立阅读

## 示例执行模式

```
1. 调用 Explore 代理 → 获取项目结构和待处理文件列表
2. 根据列表，并行调用多个 General-Purpose 代理：
   - 代理 A: 处理根目录 AGENTS.md
   - 代理 B: 处理 app/ 和 components/ 模块
   - 代理 C: 处理 lib/ 和 utils/ 模块
   - 代理 D: 处理其他小模块
3. 汇总所有代理的结果，向用户报告完成情况
```
