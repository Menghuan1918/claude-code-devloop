# Git 代码审查

审查暂存区的代码，识别潜在问题并提供改进建议。

## 功能

1. **全面审查**: 分析暂存区中所有更改的代码
2. **问题识别**: 检测潜在的 bug、安全漏洞和代码质量问题
3. **最佳实践**: 提供符合最佳实践的改进建议
4. **详细报告**: 生成结构化的审查报告

## 审查流程

1. 获取 git status 查看暂存区状态
2. 获取 git diff --staged 分析具体更改内容
3. 逐一审查每个文件的更改
4. 识别潜在问题并分类
5. 提供具体的改进建议

## 审查维度

### 代码质量
- 代码可读性和可维护性
- 命名规范和代码风格
- 重复代码和冗余逻辑
- 函数复杂度和模块化程度

### 安全性
- SQL 注入风险
- XSS 跨站脚本攻击
- 命令注入漏洞
- 敏感信息泄露
- 其他 OWASP Top 10 安全问题

### 功能正确性
- 逻辑错误和边界情况
- 错误处理是否完善
- 类型安全和类型检查
- 潜在的运行时错误

### 性能优化
- 算法效率问题
- 资源泄露风险
- 不必要的计算或 I/O 操作
- 可能的性能瓶颈

### 最佳实践
- 是否遵循项目规范
- 代码注释是否充分
- 测试覆盖是否足够
- 文档是否需要更新

## 输出格式

审查报告按以下结构组织：

1. **概述**: 总体评估和主要发现
2. **问题列表**: 按严重程度分类（严重/警告/建议）
3. **详细分析**: 每个问题的具体位置和说明
4. **改进建议**: 具体的修复方案和代码示例
5. **总结**: 是否建议直接提交或需要修改

## 特性

- **智能分析**: 基于文件类型和上下文进行针对性审查
- **优先级排序**: 按问题严重程度排序
- **可执行建议**: 提供具体可操作的改进方案
- **项目感知**: 结合项目现有代码风格和架构
